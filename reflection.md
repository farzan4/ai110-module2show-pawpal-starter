# PawPal+ Project Reflection

## 1. System Design

The user MUST be able to:

1. Create and edit pet profiles
2. create and edit pet tasks with time duration and priority
3. See today's tasks along with schedule and reasoning

**a. Initial design**

- Briefly describe your initial UML design.
- What classes did you include, and what responsibilities did you assign to each?
  Initially, I only chose Owner, Task, Pet, DailyPlan as the classes

  Owner owns the Pet objects, and has a name, owner ID, List of pets owned, and daily available minutes. You can add a pet or remove a pet to/from the owner and you can get all the tasks of the owner for all their pets.

  Pet objects have Task objects. Each Pet object has Pet ID, name, species, age, a list of special needs, and a list of tasks. You can add or remove tasks for any pet and even get the pending tasks for a pet.

  The Scheduler only processes tasks. It receives tasks and available_mins, processes an algorithm, and returns a DailyPlan.

  Each Task has a task ID, title, category, time duration, priority, and a check to see if its completed. You can mark a task complete or update its details.

  DailyPlan is generated by the Scheduler and contains a plan date, a list of scheduledTasks, a list of omitted Tasks, and a a reasoning log for the scheduled and omitted tasks. You can get the total scheduled minutes for the day and the summary of the day's plan.

**b. Design changes**

- Did your design change during implementation?
- If yes, describe at least one change and why you made it.

Yes it did. Initially I only had the Owner, Pet, Task, and DailyPlan classes but then I had to implement the Scheduler class as well. I made it because it makes sense for the Scheduler to not be a part of any of the other data classes and it will be easier to run automated tests for it as well.

Now in Phase 2 im having to take out DailyPlan because that iis how the assignment is designed.

## 2. Scheduling Logic and Tradeoffs

**a. Constraints and priorities**

- What constraints does your scheduler consider (for example: time, priority, preferences)?
- How did you decide which constraints mattered most?

**b. Tradeoffs**

- Describe one tradeoff your scheduler makes.
- Why is that tradeoff reasonable for this scenario?

The scheduler uses a greedy selection strategy: it considers tasks in priority order (and shorter duration first within the same priority), adding each task if it fits in the remaining daily time. This keeps the behavior simple and makes higher-priority tasks more likely to be included, but it does not guarantee the schedule uses every available minute or includes the greatest possible number of tasks. A combination of lower-priority tasks could sometimes fill the time more completely. This is reasonable for PawPal because respecting care-task priorities is more important than maximizing the number of tasks scheduled.
